# FSH0005: No test-surface manifest was found for this project

|                        |                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------- |
| **Warning code**       | FSH0005                                                                            |
| **Kind**               | MSBuild warning, emitted by `NetEvolve.FrameShift.targets`                         |
| **Emitted by**         | Target `FrameShiftWarnOnMissingTestSurfaceManifest`, `BeforeTargets="CoreCompile"` |
| **Severity**           | Warning (MSBuild)                                                                  |
| **Enabled by default** | Yes                                                                                |
| **Silenced by**        | `FrameShiftSuppressSetupWarning`                                                   |

This is not an analyzer diagnostic. It comes from the MSBuild assets shipped inside the package, so
it has no category, no `helpLinkUri` and it cannot be configured through `.editorconfig`,
`[SuppressMessage]` or `#pragma warning`.

## Cause

A project that FrameShift is active on is about to compile, is not itself a test project, and no
`*.frameshift-tests` file reached the compiler as an `AdditionalFiles` item. Without a manifest the
production side has nothing to seed reachability from.

The exact text is:

```text
warning FSH0005: FrameShift found no test-surface manifest for 'MyApp', so every mutation point is reported as unreachable. Build the TUnit test project first and add its generated '*.frameshift-tests' manifest to this project, or set 'FrameShiftSuppressSetupWarning' to 'true' to silence this warning. See https://github.com/dailydevops/frameshift for the documented setup.
```

The project name in the message is `$(MSBuildProjectName)`. The text names TUnit because that was the
first supported framework; the setup is the same for a test project on TUnit, xUnit, NUnit or MSTest.

## Rule description

The warning fires only when **all** of these hold:

- `$(FrameShiftEnabled)` is `true` (the default),
- `$(FrameShiftSuppressSetupWarning)` is not `true`,
- `$(DesignTimeBuild)` is not `true`, so the IDE's design-time builds stay quiet,
- `$(IsTestProject)`, `$(IsTestingPlatformApplication)` and `$(FrameShiftIsTestProject)` are all not
  `true`, so a test project is never asked for a manifest of its own, and
- no item in `@(AdditionalFiles)` has the extension `.frameshift-tests`.

Because the production analyzer stays completely silent without a manifest — it treats the absence as
"this project has not opted in" and reports no [FSH0001](FSH0001.md) and no
[FSH0003](FSH0003.md) — this MSBuild warning is the only signal that the setup is incomplete. The
sentence about every mutation point being reported as unreachable describes what you would get if a
manifest existed but contributed nothing; see [FSH0003](FSH0003.md) for that case.

## How to fix violations

The setup the warning asks for is the two-pass wiring of FrameShift:

1. **Reference the package from the test project and from the project under analysis.** The
   test-side analyzer and generator run in the test project; `MutationCoverageAnalyzer` runs in the
   production project.
2. **Build the test project.** A project that references a package whose id starts with `tunit`,
   `xunit`, `nunit` or `mstest` (case-insensitively) gets `$(FrameShiftWriteTestSurfaceManifest)`
   defaulted to `true`. Its generator emits the manifest and the target
   `FrameShiftWriteTestSurfaceManifest` writes it to
   `$(MSBuildProjectDirectory)\$(MSBuildProjectName).frameshift-tests`. Set
   `FrameShiftWriteTestSurfaceManifest` to `true` explicitly for a test project that references none
   of those packages, or to `false` to keep the analysis but never write a manifest. In a
   multi-targeting test project exactly one inner build writes the file: the one building the first
   entry of `$(TargetFrameworks)`.
3. **Commit that manifest** and make it visible to the project under analysis. Every
   `**/*.frameshift-tests` file inside the project directory is added to `@(AdditionalFiles)`
   automatically (`bin`, `obj`, `$(BaseOutputPath)` and `$(BaseIntermediateOutputPath)` are
   excluded). Since the manifest is written next to the _test_ project, the production project needs
   the file linked in — or `FrameShiftEnableDefaultManifestItems` set to `false` and the files added
   explicitly:

   ```xml
   <ItemGroup>
     <AdditionalFiles Include="..\..\tests\MyApp.Tests\MyApp.Tests.frameshift-tests" />
   </ItemGroup>
   ```

4. **Build the project under analysis.** The manifest is now present and the warning is gone.

The manifest is a checked-in artifact on purpose: the production build of a fresh clone or of CI must
see the same test surface without having to build the tests first.

## When to suppress warnings

`.editorconfig`, `[SuppressMessage]` and `#pragma warning` have no effect on an MSBuild warning. Use
the property the target provides:

```xml
<PropertyGroup>
  <FrameShiftSuppressSetupWarning>true</FrameShiftSuppressSetupWarning>
</PropertyGroup>
```

Set it when

- the project is deliberately not covered by mutation analysis, or
- the first pass has not produced a manifest yet, for example on a branch that introduces the test
  project, and you do not want the warning until it has.

Two alternatives, both coarser:

```xml
<PropertyGroup>
  <!-- Demote the warning to a message for the whole build. -->
  <MSBuildWarningsAsMessages>$(MSBuildWarningsAsMessages);FSH0005</MSBuildWarningsAsMessages>

  <!-- Turn FrameShift off entirely; this also silences the analyzer diagnostics. -->
  <FrameShiftEnabled>false</FrameShiftEnabled>
</PropertyGroup>
```

Do not suppress the warning while you still expect gap reports from the project: without a manifest
the analyzer produces none at all, and a silent build then looks like a clean one.

## Example

A solution where the package has just been added to `src/MyApp/MyApp.csproj` and to
`tests/MyApp.Tests/MyApp.Tests.csproj`, built before the tests were built once:

```console
$ dotnet build src/MyApp/MyApp.csproj
  MyApp -> ...
C:\src\MyApp\src\MyApp\MyApp.csproj : warning FSH0005: FrameShift found no test-surface manifest for 'MyApp', so every mutation point is reported as unreachable. Build the TUnit test project first and add its generated '*.frameshift-tests' manifest to this project, or set 'FrameShiftSuppressSetupWarning' to 'true' to silence this warning. See https://github.com/dailydevops/frameshift for the documented setup.
```

Building the test project first creates
`tests/MyApp.Tests/MyApp.Tests.frameshift-tests`; linking that file into `src/MyApp/MyApp.csproj` as
shown above and rebuilding produces a warning-free build that now reports real mutation coverage
gaps.
